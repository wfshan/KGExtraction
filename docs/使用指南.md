> 本文面向使用者，讲清「这是什么、能做什么、怎么用」。
> 想了解设计理念与技术架构，请读 [产品设计文档](产品设计文档.md)；想部署到服务器，请读 [部署指南](deployment_guide.md)。

---

## 一、这是什么

**KGExtraction** 是一款基于大语言模型的**可治理知识工程工作台**。它把 PDF、Word、Markdown、TXT、Excel 等非结构化文档，转化为**结构化、可溯源、可校验、可演化**的知识图谱，并支持基于图谱与原文的**多模式溯源式问答**（Graph RAG）。

与"一把梭"的全自动抽取工具不同，它走的是**中间路线**——本体（Schema）是一等公民，但支持 AI 诱导与版本化演化；每条知识锚定原文证据；发布前经过确定性校验门控。适合对**合规性、可解释性、可溯源性**有强要求的团队：法务、研报、审计、技术规范、企业知识库、科研。

### 能解决的典型问题

- 把一批领域文档（论文、规范、案例）**重构成一张可查询的知识网络**，而不是一堆全文检索结果。
- 既能抽取**表面实体**（人名、机构、日期、文件名），也能从案例中**归纳抽象知识**（概念、规则、模式）——后者是原文里不存在、需要概括出来的。
- 问答时给出**可点击的溯源链**：结论 → 支撑它的关系三元组 → 原文短句，满足审计与合规场景。
- 新文档增量摄入、图谱增量演化，而非每次全量重建。

## 二、五个核心概念

理解这五个概念，就理解了整个产品的运作方式。

### 1. 本体（Schema）——知识的类型系统

Schema 定义"这个项目关心哪些类型的实体和关系"。比如一个反洗钱审计项目，实体类型可能有「账户」「机构」「交易日期」「风控规则」，关系类型有「持股」「转账」「命中规则」。抽取严格按 Schema 进行，Schema 之外的类型不会静默丢弃，而是落为"被拒项"供你复查（它们往往是 Schema 缺口的信号）。

Schema 不用从零手写：系统能**分析文档自动建议**，也能**与你对话生成**，还能在抽取后**检测缺口诱导补全**。

### 2. 抽象度分道——知识不是只有一种

同一个本体里，知识的"抽象程度"是一条连续谱，系统据此把类型分成三档，各走不同的抽取与校验流程：

| 抽象度 | 含义 | 例子 | 证据方式 | 可信度依据 |
|--------|------|------|----------|-----------|
| **表面**（surface） | 文本中存在、可定位 | 人名、机构、文件名 | 逐字命中原文 | 置信度 |
| **标准化**（normalized） | 表面存在但需归一 | 日期→ISO、金额→数值 | 逐字 + 归一化 | 置信度 |
| **归纳**（inductive） | 原文不存在、需概括 | 概念、规则、行为模式 | 源案例摘录 + 忠实度校验 | **支撑案例数** |

关键区别：归纳知识（如从案例中概括出的一条风控规则）**在原文里逐字找不到**，所以不能用"逐字证据校验"来把关，而是靠"这条规则被多少个独立案例支撑"来度量可信度。产品全端用颜色区分——**蓝=表面、青=标准化、紫=归纳**，在 Schema 编辑、抽取计划、复核队列、图谱节点上一色到底。

### 3. 抽取计划（Plan）——本体编译出的流程

抽取流程不是一条为所有本体写死的固定流水线，而是由 Schema **编译**出来的、随本体形态变化的计划。你在「本体与计划」页能看到编译出的**泳道视图**：归纳类型走一条道（归纳抽取→结构校验→忠实度校验→语义归并），表面类型走另一条道（逐字抽取→值标准化→消歧→证据校验），最后在关系推断处汇合。每一步都可查看"为什么这么抽"的理由。这让抽取**过程本身**也变得可审查、可复现。

### 4. 三层图谱——知识如何缝合成网

抽取出的图谱有三层，分工明确：

- **知识层**：Schema 定义的实体与关系。这是问答和图算法默认工作的范围。
- **结构层**：文档的物理组织。每个文档一个「文档」节点，层次切分识别出的标题生成「章节」节点，形成 `文档 → 章节 → 片段` 三级树，片段之间有「下一段」顺序边。
- **桥接层**：把知识锚回语料。每个实体通过「提及于」边连到它出现的片段锚点——于是"一个概念在哪些文档的哪些段落被涉及"变成可遍历的路径；同片段共现但没有明确关系的实体之间，还会加低权「共现」边兜底。

这套设计解决了"孤立节点"问题：即使一个实体没抽出任何领域关系，它也会通过「提及于」边挂在来源片段上，不再是图上的孤点。

### 5. 治理闭环——LLM 提案、确定性引擎裁决

产品的可信度来自一条原则：**大模型只负责"提案"，确定性引擎负责"裁决"**，绝不用 LLM 检查 LLM。

- 抽取结果先进**草稿图**，不直接可信。
- 发布前经过**确定性门控**：类型是否在 Schema 内、关系两端类型是否合法、证据是否命中原文……只有通过校验的知识才能进**发布图**。
- 你在**复核队列**里逐项裁决（通过/拒绝/就地改类型），全程写审计日志。
- 复核的修改沉淀为经验，反哺后续抽取。

## 三、快速开始

### 环境要求

- Python 3.9+（推荐 3.11）
- Node.js 18+
- 一个 OpenAI 兼容的大模型 API Key（默认对接阿里云百炼 DashScope）

### 一键启动（本地开发）

```bash
# 1. 配置环境变量
cp .env.example .env
# 编辑 .env，至少填入 DASHSCOPE_API_KEY

# 2. 一键启动前后端
chmod +x startup.sh
bash startup.sh
```

启动后访问：

- 前端工作台：<http://localhost:5173>
- 后端 API 文档：<http://localhost:8000/docs>

### 手动启动（分别调试）

```bash
# 后端
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload

# 前端（新终端）
cd frontend
npm install
npm run dev
```

### Docker 部署

生产环境推荐 Docker，详见 [部署指南](deployment_guide.md)：

```bash
cp .env.example .env   # 填入 API Key
docker-compose up --build -d
```

## 四、界面导览：四个工作区（逐功能详解）

产品采用**统一左侧导航**，顶部是项目切换器，下方是四个工作区，导航项上带**实时状态徽标**（解析中、运行中、待复核数、门控违规数），让你在任何位置都知道"哪里需要处理"。底部是系统配置。

> 项目是全局上下文而非步骤——随时可以在左上角切换项目，各工作区的内容会跟着切换。

> 下面每个功能都按「**作用 / 什么时候用 / 怎么用**」三段说明，第一次使用照着做即可。

---

### 工作区一 · 数据接入

把原始文档变成系统能处理的"分片"，是一切的起点。

#### 上传文档

- **作用**：把你的文档喂给系统，自动解析成纯文本并切成一小段一小段（"分片"，chunk），后续抽取以分片为单位进行。
- **什么时候用**：项目建好后第一步；后续有新文档也在这里追加。
- **怎么用**：把文件拖到上传区，或点击选择。支持 **PDF / TXT / Markdown / DOCX / CSV / XLSX**。上传后系统在**后台**解析分片，文档状态从"解析中"变为"已解析"，界面会自动刷新——不用一直等着，可以先去做别的。
- **注意**：内容完全相同的文件重复上传会被**拦截**（按内容哈希去重），防止重复抽取污染图谱、浪费钱。

#### 切片策略（每个文档可单独设）

切得太碎会丢上下文，切得太大会稀释重点。三种策略按文档形态选：

| 策略 | 怎么切 | 适合 |
|------|--------|------|
| **固定长度滑动窗口** | 按字符数切，段间留重叠 | 通用默认，不确定就用它 |
| **按段落严格切分** | 按空行分段，一段一片 | 段落清晰、每段独立成义的文本 |
| **结构化层级切分** | 按标题深度切，每片带上级标题作上下文 | 有明确标题层级的规范/报告 |

> **结构化层级切分的适用范围**：只对 **Markdown** 和**带标题样式的 DOCX** 真正生效——它们保留了标题层级，切出来的片段能挂到"章节"节点上（见三层图谱）。**PDF** 解析后标题信息会丢失，仅当正文含"第X章 / 1.1 / 一、"等编号样式时能识别，否则退化为整体切分。上传界面对此有提示。

已上传的文档，可点"重新切片"换策略重切（Markdown 会重读原文以恢复标题，其他格式基于已解析文本）。

#### 冷启动导入（图谱数据导入）

- **作用**：如果你**已经有**一份现成的知识图谱（JSON 格式的节点+边），直接导进来当起点，不用从文档重新抽。系统会从导入数据**反推出 Schema**，并把它纳入同一套治理体系（类型校验、审计留痕）。
- **什么时候用**：手头已有历史图谱、想在它基础上继续扩充；或想快速搭个初始图谱试跑问答。
- **怎么用**：在"图谱数据导入（冷启动）"区先**下载模板**看清 JSON 格式（节点要有名称+类型，边要有源/目标/关系），按模板填好后上传。导入的节点来源会标记为 `cold_start`，与后续抽取的知识可以合并（同名同类型自动并为一个节点）。

### 工作区二 · 本体与计划

这是全产品**最需要花心思**的一步——本体（Schema）定义准了，抽取质量才有保证。页面顶部有一条**引导主线**（① 智能建议 → ② 智能规划），复杂能力收在「高级」下拉里。下面按你会用到的顺序讲。

> **先分清三个 LLM 入口，别用混了**：
> - **① 智能建议**：AI 读你的文档，**自动**替你想出该有哪些类型（你没头绪时用）。
> - **对话配置**：你**主动告诉** AI 想抽什么，边聊边定（你心里有具体要求时用）。
> - **② 智能规划**：类型定好后，让 AI 判断每个类型该走"表面抽取"还是"归纳抽取"并编译流程（定完类型后用）。
> 简单说：**建议/对话** 解决"有哪些类型"，**规划** 解决"每种类型怎么抽"。

#### ① 智能建议

- **作用**：AI 通读你上传的文档，自动提议一套实体类型和关系类型（含每个类型的抽象度标注），一键填好 Schema。
- **什么时候用**：刚开始、对该领域该抽哪些类型**没有明确想法**时。这是最省事的起点。
- **怎么用**：点「① 智能建议」，稍等 AI 分析（旁边有实时日志）。生成后会**直接覆盖**当前 Schema，你在下方类型列表里检查、增删、改定义即可。若项目里同时有多种数据来源（如文档 + 冷启动导入），会先弹窗让你选基于哪个来源分析。

#### 对话配置（高级）

- **作用**：用**聊天**的方式和 AI 一起定 Schema。AI 先给你一段"这批文档大致讲了什么"的开场分析，你再用大白话说清想抽什么、来回讨论，满意后一键把对话转成 Schema。
- **什么时候用**：你对要抽什么**有具体想法或特殊要求**（比如"我只关心资金流向，不要人物关系"），想主动引导，而不是让 AI 全权决定。
- **怎么用**：「高级 → 对话配置」打开右侧对话面板 → 顶部会**自动**流式加载一段文档总结作为开场 → 在底部输入框描述你的业务场景/想抽的实体（如"从审计案例里抽出可复用的风控规则，规则要有触发条件"）→ 可多轮追问调整 → 满意后点右上角**「生成 Schema」**，对话内容被规范化成 Schema 填入。

#### ② 智能规划（编译抽取流程）

- **作用**：类型定好后，让大模型逐个判断——这个类型是"表面可定位的"（人名、日期，走逐字抽取）还是"需要从案例概括的"（规则、概念，走归纳抽取），并规划出对应的抽取步骤，写回每个类型的抽象度。**你不用配任何技术参数**。
- **什么时候用**：类型列表基本定稿后，正式抽取**之前**。尤其当你的本体里含"概念/规则/模式"这类抽象知识时，这一步几乎必做——否则它们会被当普通实体错误处理。
- **怎么用**：点「② 智能规划」打开面板 →（可选）用一句话描述你的抽取意图（如"从审计案例中抽出可复用的风控规则"）→ 点「开始规划」→ AI 给出每个类型的**抽取语义**（抽象度 + 是否归纳），你可逐项调整 → 确认应用，抽象度写回 Schema，下方泳道随即更新。

#### 手动编辑类型 + 结构模板

- **作用**：直接增删改类型。每个实体类型可设**名称、抽象度、定义、示例**。定义写得越清楚，AI 抽得越准。
- **结构模板**（仅归纳类型）：选类型为"归纳知识"时会展开一个结构模板区，你可以规定这类归纳产物**必须具备哪些字段**（如"风控规则"必须有"触发条件""风险类别"，可标必填/可选）。抽取后由结构校验**挡掉缺字段的空泛归纳**（比如只写了"资金异常"却没写具体触发条件的规则会被拦下）。
- **怎么用**：在实体/关系列表里点"添加"或直接编辑。关系类型要指定源/目标实体类型（可多选，留空=不限）。**保存时系统会校验**关系两端的类型必须已定义，防止产生"永远命不中"的悬空关系（若违规会红字提示）。

#### 缺口演化（高级）—— 让 Schema 越用越全

- **作用**：抽取跑完后，系统对比"实际抽出/被拒的类型"和"当前 Schema"，找出**没覆盖到的高频类型**（包括抽取时因不在 Schema 中而被拒的 out-of-schema 类型），诱导你补全，并**存为新版本**。让 Schema 从"一次性写死"变成"随数据成长"。
- **什么时候用**：**第一次抽取之后**。如果复核时发现"被拒项"里反复出现某个本该抽的类型，就来这里补。
- **怎么用**：「高级 → 缺口演化」打开面板 → 系统自动检测并列出缺失的实体/关系类型（会告诉你"抽取阶段有 N 项因类型不在 Schema 中被拒绝"）→ 点「预览演化」让 AI 诱导出这些新类型的完整定义 → 检查预览 → 点「确认应用为新版本」。**当前 Schema 会自动存为历史版本**（面板底部有版本历史表，随时对照），新类型合入。之后重跑抽取，这些原本被拒的知识就能进图了。

#### 抽取计划泳道（页面下方常驻）

- **作用**：把上面「智能规划」编译出的抽取流程**画出来**给你看——这是产品"本体编译流程"理念的可视化落点。
- **怎么看**：泳道按抽象度分道渲染——**紫=归纳道**（归纳抽取→结构校验→忠实度校验→语义归并）、**蓝=表面道**（逐字抽取→值标准化→消歧→证据校验）、**灰=汇合道**（关系推断、冲突检测）。每一步**悬停**可看它的中文名、作用于哪些类型、"为什么这么排"的理由和参数。Schema 保存或重新规划后，泳道自动刷新。你只需确认它符合预期，无需改任何东西。

### 工作区三 · 抽取与治理

真正把文档抽成图谱、并守住质量的地方。分「抽取运行」和「复核与发布」两个标签页。

#### 抽取目标配置（每个文档单独设）

- **作用**：指定"这个文档只抽哪些类型"。不配则默认抽全部 Schema 类型。
- **什么时候用**：不同文档侧重不同（如合同文档只抽条款、名录文档只抽机构）时，缩小范围能**省 token、提质量**。
- **怎么用**：在文档列表里展开某文档，勾选它要抽的实体/关系类型。

#### 启动抽取（含成本预估）

- **作用**：把选定文档按抽取计划跑一遍，结果写入**草稿图**（不直接可信，等复核）。
- **怎么用**：点「启动抽取」→ 先弹**成本预估**（预计调用次数、token、费用）。若 Schema 含归纳类型，预估会**单列归纳分道的额外开销**（归纳更贵更慢，心里有数）→ 确认后开跑。
- **看进度**：进度用**分片点阵**展示——每格约一个分片，**绿=完成、蓝色脉冲=正在处理**，一屏看出整体节奏和当前卡在哪。旁边是实体/关系/归纳知识的**实时计数**。下方**执行日志**按语义着色：**紫=归纳治理事件**（归纳/语义归并）、黄=警告、红=错误、绿=完成——关键事件天然醒目。

#### 继续 / 重启 / 增量抽取

三个动作别搞混：

- **继续抽取**：上次因 token 预算用尽等原因**中途停了**，点这个从断点接着跑，已抽结果不受影响。
- **重新抽取（重启）**：**清空当前图谱从头再来**。改了 Schema 想彻底重抽时用——会有二次确认，因为它会丢弃已有草稿。
- **增量抽取新文档**：只处理**上次抽取后新上传**的文档，与既有图谱**合并**（不清空）。日常新增文档时用这个，而不是重启。

#### 复核与发布

抽取结果先进草稿图，你在这里逐项裁决，只有通过的才发布进"已发布图"。

- **先看四张治理指标卡**：门控违规数 / 待复核增量 / 归纳知识<2例支撑数 / 证据逐字验证率——第一眼就知道哪里最需要你。
- **风险色条**：复核队列每行左侧有色条，**红=门控违规、黄=高风险**，凭颜色快速分诊。
- **按抽象度分道显示**：证据列和可信度列会自动切换口径——表面知识看"逐字已验证/未命中"，归纳知识看"忠实度通过 / N 例支撑"。
- **过滤**：可「仅看高风险」，或点违规原因标签按原因聚合过滤，批量处理同类问题。
- **就地修正违规项**：点行内**扳手图标**，可直接把节点**改成 Schema 内的类型**，或**把当前类型加入 Schema**——不用跳回本体页。
- **裁决**：逐项**通过 / 拒绝**，或检查完整体**发布**。
- **⚠️ 重要**：门控违规项**即使你手动"通过"，发布时仍会被确定性门控过滤掉**——这是"可信知识"的最后守门人。想让它进图，必须先修正类型或补进 Schema，把违规解除。
- **审计日志**（标签内）：以**时间线**呈现"谁·何时·对哪条知识·做了什么"，全程留痕可追溯。

### 工作区四 · 图谱与问图

看图谱 + 基于图谱问答。原独立的图谱页已并入这里。

#### 图谱可视化

- **作用**：把抽出的知识图谱画成力导向图，直观看实体和关系。
- **怎么看**：节点**按类型着色、带辉光**；**归纳知识节点用菱形 + 紫色虚线边框**，一眼区别于表面实体。
- **探索模式（默认）**：不一次性渲染整张大图（会卡），而是**从搜索框输入实体名逐个加入画布**，再按需展开它的邻居。大图（>500 节点）自动切换更稳定的同心圆布局防抖动。
- **切换视角**：可在"已发布图 / 草稿图"间切换；可开关**"文档结构层"**看到 文档→章节→片段 的骨架（默认只看知识层）。

#### 问图（Graph RAG）

- **作用**：用自然语言问图谱，AI 结合"图谱关系 + 原文片段"作答，并给出可点击的溯源。
- **怎么用**：打开问图面板直接提问。检索方式**默认智能路由**——系统按问题类型自动选（单跳事实→文本检索、实体邻域→子图扩展、多跳关联→PPR 二部图、全局主题→社区摘要）。其余 7 种模式收在"高级"里，一般不用手动选。
- **看溯源**：回答**流式生成**的同时，图上会**点亮本次命中的子图**（命中满亮+辉光，其余降为背景，底部有"命中高亮中·点击清除"）。回答里的关键结论带 **[来源#n] 引用锚**，**点击即弹出被引用的原文片段全文**——这就是"结论 → 关系三元组 → 原文短句"的完整溯源链。
- **多轮对话**：按浏览器会话隔离，可随时「新会话」重开或「清空」。

#### 构建社区摘要（问全局问题的前提）

- **作用**：对整张已发布图做社区检测 + 分层摘要，让系统能回答"**这批文档整体讲了什么**"这类宏观/主题问题。
- **什么时候用**：想问全局性问题时。**不构建的话，智能路由遇到全局问题会没有摘要可用。**
- **怎么用**：问图面板里点"构建社区摘要"（**需要图谱已发布**）。构建后会提示检测到几个社区、生成几条摘要。之后智能路由会自动把全局型问题路由到社区摘要模式。

## 五、一条完整的使用路径

以"从一批论文构建知识图谱并问答"为例：

1. **建项目**：左上角项目切换器旁的文件夹图标 → 新建项目。
2. **传文档**（数据接入）：上传若干 PDF，等状态变为"已解析"。
3. **配本体**（本体与计划）：点「① 智能建议」让 AI 分析出类型（或用「对话配置」自己主导）→ 点「② 智能规划」标注抽象度并编译计划 → 检查下方泳道确认无误 → 保存。
4. **抽取**（抽取与治理 → 抽取运行）：确认成本预估 → 启动 → 看点阵跑完。
5. **复核发布**（抽取与治理 → 复核与发布）：先看指标卡，处理红色违规项（就地改类型或拒绝），其余通过 → 发布。
6. **补 Schema 缺口**（本体与计划 → 高级 → 缺口演化）：如果复核时"被拒项"里反复出现某个本该抽的类型，来这里预览并应用为新版本，然后回第 4 步重抽——原本被拒的知识就能进图。
7. **问答**（图谱与问图）：如需问全局问题先「构建社区摘要」；打开问图用智能路由提问，看回答的 [来源#n] 溯源到原文，图上看命中子图。
8. **增量演化**：有新论文时回到数据接入上传，然后在抽取页用「增量抽取新文档」（只处理新增、与既有图谱合并，不要用"重启"）。

## 六、系统配置

工作台左下角的齿轮图标打开系统配置：

- **模型选择**：轻量/均衡/强力三档，按任务复杂度自动路由。

关键环境变量（`.env`）：

| 变量 | 说明 |
|------|------|
| `DASHSCOPE_API_KEY` | 大模型 API Key（必填） |
| `BASE_URL` | 大模型 API 地址，默认百炼，可换任意 OpenAI 兼容服务 |
| `KG_ACCESS_TOKEN` | 访问令牌，配置后所有请求需携带 `Authorization: Bearer <令牌>`，**网络/团队部署必须配置** |

## 七、常见问题

**Q：抽取完图里有很多孤立节点，正常吗？**
A：抽取后这些节点会通过「提及于」边挂到来源片段锚点上，不再是真正的孤点。如果你在默认视图（只看知识层）里看到孤点，说明它没抽出领域关系——可以开"文档结构层"看到它的语料归属，或检查 Schema 关系类型是否覆盖不足（"共现"兜底边也会提供线索）。

**Q：一个概念在两篇文档都出现，图里是一个节点还是两个？**
A：一个。系统用 `(类型, 名称)` 作为实体身份，同名同类型自动合并，来源片段取并集。通过「提及于」边能遍历到它涉及的所有文档片段。

**Q：归纳出的规则/概念，可信度那个百分比是怎么来的？**
A：归纳知识**不看**百分比置信度，看**支撑案例数**——有多少个独立片段归纳出同一条知识。复核队列里归纳项显示"N 例支撑"，仅 1 例的需重点复核。措辞不同的同义归纳会被语义归并合并、案例数累加。

**Q：为什么我"通过"了一个违规项，发布后还是没进图？**
A：这是有意设计。人工复核通过不等于豁免门控——确定性门控是可信知识的最后守门人。请先修正类型或把类型加入 Schema（复核行的扳手图标可就地操作），违规解除后才能发布。

**Q：层次切片对我的 PDF 没生效？**
A：PDF 解析后标题层级信息会丢失。层次切分只对 Markdown 和带标题样式的 DOCX 真正有效；PDF 仅当正文含"第X章/1.1/一、"等编号样式时可识别，否则退化为整体切分。上传界面有相应提示。

**Q：问图能问"这批文档整体讲了什么"这类宏观问题吗？**
A：能，但需要先在问图面板构建**社区摘要**（对已发布图做社区检测 + 分层摘要）。构建后智能路由会自动把全局型问题路由到社区摘要模式。
